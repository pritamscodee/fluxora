## Context

ADR-0001 named Cloudflare R2 as the blob store. Development needs a local equivalent, and
the obvious choice was MinIO in Docker. Two things then became clear.

**MinIO's images are no longer publicly pullable.** `minio/minio` on Docker Hub and
`quay.io/minio/minio` both refuse anonymous pulls — verified 27 October 2026: Docker Hub
returns "pull access denied … repository does not exist", quay.io returns 401 on the
manifest HEAD and on its tags API. A default `docker compose up` therefore cannot bring up
MinIO on a clean machine.

**The store does not need to be MinIO.** R2, AWS S3, MinIO and SeaweedFS all speak the
same S3 API. What the pipeline actually depends on is narrow: SigV4 signing, presigned PUT
and GET, `head_object`, prefix listing, and bulk delete.

## Decisions

### One backend for every environment

`S3Storage` is selected by `S3_ENDPOINT` plus credentials. Path-style addressing and SigV4
are the defaults, because MinIO and SeaweedFS require them and R2 accepts them. There is no
vendor-specific code path.

### SeaweedFS is the default dev container; MinIO is a compose profile

Both publish the S3 API on `localhost:9000` with the same credentials, so configuration is
byte-identical and the application cannot tell which is running.

```bash
docker compose up -d                   # SeaweedFS, works on a clean machine
docker compose --profile minio up -d   # MinIO, once you have registry access
```

### Buckets are created on first use

`ensure_bucket()` runs at construction, tolerating both "already exists" and a lost
creation race. A fresh container starts with no buckets, and the first upload would
otherwise fail with `NoSuchBucket`.

### Presigned PUTs do not sign `Content-Type`

Including it forces the client to reproduce the header byte-for-byte, which browsers do
not do reliably; the mismatch surfaces as an opaque 403 at upload time.

### `S3_PUBLIC_ENDPOINT` for split-horizon deployments

A presigned URL's signature covers the host, so one signed against an in-cluster hostname
breaks the moment a browser uses it. When set, a second client signs client-facing URLs
against the public origin.

## Consequences

- Swapping to R2 or AWS S3 in production is configuration, not code.
- The dev store is not the same implementation as production. Mitigated by the test suite
  running unchanged against either via `FLUXORA_TEST_STORAGE=s3`, which covers the
  presigned-upload path over a real socket rather than a filesystem shim.
- SeaweedFS's S3 gateway is a smaller surface than MinIO's; if a test ever needs a MinIO
  behaviour specifically, the profile is already defined.
- A local filesystem backend remains as a third fallback when no credentials exist at all,
  so the full upload-to-playback path runs with no infrastructure whatsoever.

## Verified behaviour

<Callout kind="note" title="Checked against the running container, not assumed">
The backend was confirmed to auto-create the bucket; store and read back exact bytes;
overwrite in place on a repeated write (which is what makes job retries converge rather
than duplicate); report nothing for a missing key; complete a presigned PUT and GET round
trip; refuse an unsigned GET with 403, keeping the bucket private as ADR-0001 requires;
and remove a whole prefix recursively.
</Callout>
