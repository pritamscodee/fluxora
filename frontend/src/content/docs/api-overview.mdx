Base URL `https://api.fluxora.dev`, or `http://localhost:8000` locally. Everything lives
under `/v1`. Interactive reference at `/docs`, OpenAPI schema at `/openapi.json`.

## The envelope

Every success response wraps its payload in `data`:

```json
{ "data": { "id": "Qdh4pm..." } }
{ "data": [ { "id": "Qdh4pm..." } ] }
```

Errors use one shape, always:

```json
{
  "error": {
    "type": "invalid_parameters",
    "messages": ["input: must contain exactly one entry of type 'video'"]
  }
}
```

`type` is machine-readable and stable; `messages` is a list because validation usually has
more than one thing to say.

| HTTP | `error.type` |
| --- | --- |
| 400, 422 | `invalid_parameters` |
| 401 | `unauthorized` |
| 403 | `forbidden` |
| 404 | `not_found` |
| 409 | `conflict` |
| 429 | `rate_limited` |
| 500 | `internal_error` |
| 503 | `model_unavailable` |

### Dashboard — Bearer

```bash
curl localhost:8000/v1/auth/me -H "authorization: Bearer $ACCESS_TOKEN"
```

HS256, 30-minute access tokens, 30-day rotating refresh tokens.

### Video API — Basic

```bash
curl -u "$KEY_ID:$SECRET" localhost:8000/v1/video/assets
```

An API key resolves to exactly one project, so **no `/v1/video/*` endpoint takes a project
id**. That removes a class of cross-tenant bug by construction rather than by checking.

Secrets are Argon2id-hashed. A key id that does not exist is still hashed against a decoy
so a missing key and a wrong secret take the same time.

<Callout kind="note" title="Revoked, not deleted">
Deleting an API key sets `revoked_at`. The row stays as the audit record of what was used
and when. A revoked key returns 403 — distinguishable from 401 for an unknown key, which
makes "my key stopped working" diagnosable.
</Callout>

## Rotating refresh tokens

<Endpoint method="POST" path="/v1/auth/refresh" auth="public" />

Each refresh consumes the presented token and issues a new pair. Presenting an
already-spent token means it leaked, so the **entire token family for that user is
revoked**, not just the one request rejected.

```
register → refresh_1
refresh_1 → refresh_2    (refresh_1 now revoked)
refresh_1 again → 401, and refresh_2 is revoked too
```

## Pagination

```
?limit=25&page=1
```

`limit` is 1–100 (default 25), `page` is 1-based. Out-of-range values are 422, not
silently clamped. The total count comes back in `X-Total-Count`.

## Unknown fields are rejected

```bash
curl -u "$KEY" -X POST .../v1/video/uploads -d '{"timeuot": 600}'
# 422 invalid_parameters
```

A typo must not be silently accepted. The alternative — accepting and ignoring it — means
a caller sets `timeuot` and spends an afternoon wondering why the timeout never changes.

## Idempotency

Mutating API-key endpoints accept `Idempotency-Key`:

```bash
curl -u "$KEY" -X POST .../v1/video/uploads -H 'idempotency-key: order-12345'
```

The key, a fingerprint of the request, and the response are stored for 24 hours. A replay
with the same key returns the stored response; the same key with a **different body** is a
409 rather than a silent second execution.

## Timestamps and identifiers

RFC 3339 UTC (`2026-10-27T12:00:00Z`). Durations are float seconds.

Public ids are opaque base58 strings from an alphabet with no `0`, `O`, `I` or `l`, so
they survive being read aloud or hand-copied. They are unguessable and reveal nothing
about volume or ordering. Prefixed ids (`evt_`, `fx_`, `sk_`, `whsec_`) make it obvious
what a string is when it turns up in a log.
